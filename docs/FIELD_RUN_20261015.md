## Imager procedure — only after separate flash approval

1. Keep both existing cards labeled and out of the selected card reader.
   Identify the new spare by its model/capacity; writing erases that card.
2. In Raspberry Pi Imager, select Raspberry Pi 4 and **Use Custom** for the
   exact `.img.xz` above. No manual decompression is required. If the picker
   cannot open WSL's share, copy the image and both sidecars to a Windows
   folder, then hash that copy with PowerShell `Get-FileHash -Algorithm SHA256`.
3. Select only the spare card. **Skip OS customisation**: preserve the image's
   baked account, public-key-only SSH, country and network policy. Do not
   inject Wi-Fi credentials or enable password SSH through Imager.
4. After approval, write and let Imager finish its verification; do not skip
   verification. Safely eject the card. Windows may offer to format Linux
   partitions: cancel that prompt.
5. A later, separately approved shutdown/card swap/boot begins hardware
   acceptance. Keep the old card intact for comparison or rollback.

Imager reference: [official Raspberry Pi installation procedure](https://www.raspberrypi.com/documentation/computers/getting-started.html).

## Pi 4 acceptance order

1. **Boot and baseline, after approved card swap/boot.** Use Ethernet SSH.
   Independently verify the newly generated SSH host key at the Pi console
   before replacing only its obsolete known-host entry. Check the baked
   revision, running kernel, selected module path/vermagic/hash, REDUXCAP
   mount, global/configured US, RF blocks, three Redux units and Bettercap's
   unauthenticated loopback HTTP 401. Gather `sudo redux-report --summary`
   and the laptop field checker; share only sanitized observations.
2. **Actual monitor operation.** Record the selected interface's `iw` mode,
   ARPHRD type, and read-only `nexutil -I <selected-interface> -m` result.
   Primary-interface relabeling alone does not activate the separate native
   monitor lifecycle. Type 1 or firmware mode 0 keeps RF acceptance open;
   stop before changing interfaces, firmware mode, country or services.
   Prepare a specific bounded native-monitor-interface test for separate
   approval if that mismatch persists. Do not repeat the previous interface
   experiment or reload drivers automatically.
3. **Passive packet evidence, with test approval.** On an operator-owned AP,
   collect bounded local evidence of real received and decoded 802.11 frames.
   Confirm ARPHRD 801/803 and independently inspect actual capture framing:
   PCAP DLT 105 (802.11) / 127 (radiotap), or corresponding pcapng interface
   link type. ARPHRD and PCAP DLT are different number spaces. Frame counts,
   decoder success and private owned-AP sightings must agree. Runtime events
   and RX byte counters alone do not pass. No active RF transmissions are
   needed. Never upload raw captures or radio identifiers.
4. **Rotation and handoff.** Observe at least one configured interval
   (default 300 seconds). Require a real closed nonempty capture, successful
   transition out of the engine-owned active file, and a corresponding
   handoff counter. Do not ingest or manually move an open capture.
5. **Conversion and ledger.** Read `redux pipeline --config
   /etc/redux/pipeline.toml status` and worker heartbeat. Require a matching
   closed-source ledger record, actual ARM64 hcxpcapngtool success and a
   verified output when the owned-AP capture contains suitable handshake
   material. A management-only capture need not yield a handshake/hash;
   distinguish legitimate no-material results from conversion errors.
   No cracking, recovery apply or capture deletion is part of this plan.
6. **Doctor and persistence.** Check `redux live doctor`, fresh checkpoints,
   failure streak, storage and pipeline findings. Ethernet framing while
   running must show degraded RF health. Healthy framing alone must not be
   called reception. A separately approved cold boot must preserve country,
   storage and processing data without manual runtime repairs.
7. **480×320 TFT after headless gates.** Enumerate actual framebuffer/input
   nodes with `redux-display-diag`; never guess fb0/fb1. Run
   `redux-fbui --framebuffer /dev/fbN --check` on the measured node and require
   480×320, 16bpp and valid stride. Separately approve the first `--once`
   pixel write, then visually verify color order, rotation and actual Redux
   telemetry, including RF failures. Select a real touch node only after
   inventory; approve a bounded read-only sample and manual swipe test.
   Persistent display configuration/service enablement needs its own approval.

Stop on kernel/driver errors, unexpected link loss, storage faults or identity
mismatch. Preserve evidence and diagnose; no forced module removal, blind
retry, reflash or reboot. Detailed gates: [FIELD_ACCEPTANCE.md](FIELD_ACCEPTANCE.md)
and [DISPLAY_ACCEPTANCE.md](DISPLAY_ACCEPTANCE.md).
